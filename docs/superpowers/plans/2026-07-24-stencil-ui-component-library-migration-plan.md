# Stencil UI Component Library Migration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the native `@guyantools/ui-core` preimplementation with a Stencil-built Custom Element library, while preserving the Vue compatibility layer, plugin import paths, and desktop `Ui*` call contracts.

**Architecture:** `@guyantools/ui-core` owns Stencil component source, `--gt-*` tokens, loader, generated element types, Vue proxies and React proxies. `@guyantools/ui-vue` consumes the generated Vue proxies and supplies only the existing Vue-specific `v-model`, slot, expose-method and overlay compatibility wrappers. `@guyantools/plugin-ui` remains a facade over the core package and forwards its framework entrypoints.

**Tech Stack:** Stencil, `@stencil/vue-output-target`, TypeScript, Vue 3, Vue Test Utils, Vitest, jsdom, pnpm workspaces, SCSS, Electron/Vite.

---

## Migration rules

- The committed native implementation in `packages/ui-core/src/elements/` is a temporary precursor. Replace it with Stencil source; do not keep two registrations for the same `gt-*` tag.
- Keep public package names and plugin exports `.`, `./tokens.css`, `./vue`, and `./react` stable.
- Keep `ui-vue` as a compatibility package. Generated proxies are internal inputs, not a reason to drop legacy `Ui*` APIs.
- Do not migrate date/time, menu, tree, file, color, transfer, scrollbar, icon picker, or media crop components.
- Do not stage unrelated plugin-host working-tree changes.

## File map

- Modify `packages/ui-core/package.json`, `tsconfig.json`, and replace `vite.config.ts` with `stencil.config.ts`: Stencil compiler, `dist/custom-elements`, loader, Vue proxy and React proxy output targets.
- Create `packages/ui-core/src/components/gt-*/`: Stencil components for the 15 first-wave controls and an overlay controller.
- Create `packages/ui-core/src/global/gt-tokens.css`: canonical token stylesheet entry. `src/components.d.ts` is generated by Stencil and must not be hand-written.
- Replace `packages/ui-core/src/elements/`, `register.ts`, `vue.ts`, and `react.ts`: native precursor source must not survive as a second runtime.
- Modify `packages/ui-vue/src/`: consume generated proxies and retain only public Vue compatibility wrappers/tests.
- Modify `packages/plugin-ui/`: facade exports target Stencil loader and package CSS instead of local hand-written elements.
- Modify desktop compatibility entries, selected consumers, aggregate verification and docs exactly as defined below.
