# Windows 小抄与 Markdown 题库设计

日期：2026-10-13。状态：待用户确认的设计草案，尚未实现或验证运行行为。

## 1. 目标与范围

在 GuYanTools 内增加 Windows 专用小抄功能：本机正常显示独立窗口，调用系统提供的窗口捕获排除能力；用户提前维护 Markdown 题库，按题目标题搜索并阅读；所有产品操作具有键盘路径，阅读期间的核心操作支持全局快捷键。

用户明确要求兼容腾讯会议、飞书会议、Teams、Zoom、OBS、Windows 截图，并覆盖浏览器屏幕共享。以上全部进入验收矩阵，分别记录实测结果，不能用一个应用的测试代替其余应用。

第一期包括题目新增、编辑、删除、Markdown 文件导入导出、标题搜索、阅读、窗口显隐、置顶、透明度、移动、调整大小、快捷键配置与冲突反馈。题库离线存储。暂不扩展云同步、AI 答题、OCR 或插件开放接口。

## 2. 当前源码依据

- `desktop/package.json` 使用 Electron 37.2.1、Vue 3、TypeScript，已有 `marked` 与 CodeMirror，不需要引入新的框架。
- `desktop/src/main/knowledge/quick_note_window.ts` 已有透明、置顶、独立 HTML 入口与窗口生命周期模式，可沿用结构，但不修改速记窗口的业务语义。
- `desktop/src/main/screenshot/pin_window.ts` 已有贴图窗口及透明度相关实现，可复用适用的处理方式。
- `desktop/src/main/windows/persisted_window_bounds.ts` 是现有窗口位置持久化 helper，实施前确认接口并复用多屏可见区域修正。
- `desktop/src/main/shortcuts/service.ts` 已实现系统快捷键注册、占用检查、重试与插件快捷键冲突处理；新增快捷键必须接入统一服务。
- `desktop/src/shared/shortcuts.ts` 已有 accelerator 规范化与键盘事件匹配逻辑。
- `desktop/src/windows/main/pages/Knowledge/utils/markdown_enhanced_render.ts` 与 `markdown_sanitize.ts` 已有 Markdown 渲染和 HTML 清理能力；独立窗口可以复用纯工具函数，不加载主窗口 store。
- `desktop/vite.renderer.config.ts` 已配置多个独立窗口 HTML 入口，可增加 `cheat_sheet.html`。
- 本地 `node_modules/electron/electron.d.ts` 说明：Windows 的 `setContentProtection(true)` 使用 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`；Windows 10 2004 起支持从捕获中排除，更早版本可能出现黑块。`setOpacity` 在 Windows 可用。

以上是当前源码/API 定义证据，不构成防捕获兼容性实测证据。工作区已有大量未提交修改，实施时对涉及的既有文件先读 diff，仅叠加本功能。

## 3. 方案选择

推荐 **Electron 独立原生窗口 + 独立本地题库**：系统内容保护、真实窗口透明度和全局快捷键都在主进程处理；窗口内 Vue 提供题库工作流。现有技术栈可覆盖需求，影响范围清晰。

其他方案：复用知识库页面可减少题目存储代码，但会引入知识库节点、权限与主窗口耦合；独立 Win32/WPF 应用可更直接控制原生窗口，但需要新的客户端和分发流程。第一期不选这两种方案。

## 4. 窗口行为与捕获保护

### 4.1 创建与显示

- Windows 10 2004（build 19041）及更高版本、Windows 11 为目标系统。更早版本明确标识不满足“从捕获中完全排除”的目标，不能显示兼容性已通过。
- 使用单个按需创建的 `BrowserWindow`，无系统边框、默认置顶、透明背景、默认大小 520 × 640，最小大小 360 × 280。窗口默认不打开，用户从应用入口或全局快捷键唤起。
- 首次显示前必须应用 `setContentProtection(true)`，再恢复透明度与位置，加载完成后显示，避免未保护的首次闪现。
- 默认透明度 90%，允许 20%～100%，每次快捷键调整 5 个百分点；主进程限制范围并拒绝 NaN/Infinity。透明度作用于整个原生窗口，背景和文字一起变化。
- 提供置顶切换、键盘移动与调整大小，位置恢复时校正到现有显示器工作区。正常隐藏保留阅读状态；显式关闭销毁窗口，下次唤起可重新创建。
- 系统/API 检查失败时保持窗口隐藏，返回可理解的错误；不能无提示地降级为可被捕获的窗口。

### 4.2 能力边界

内容保护是操作系统提供的捕获排除机制。第三方应用的捕获路径、软件版本与系统版本都会影响实际效果，不能承诺“任何方式永远无法捕获”。外部摄像设备拍摄不在该能力范围内。

`isContentProtected()` 只能用于检查 Electron 保护状态，不能据此宣布所有会议软件通过。验收必须查看共享接收端或最终录制画面：本机窗口可见，输出画面中没有题目、窗口边框或窗口黑块残影，且底层共享内容正常显示。

新增、编辑、删除确认、帮助与快捷键配置使用受保护窗口内部视图；不把题目正文弹到主窗口、系统通知或日志中。系统文件选择器不属于本功能窗口，不宣称其受保护，用户可提前完成导入导出。

## 5. 题库与 Markdown

### 5.1 数据与持久化

题目结构：`id`（UUID）、`title`（非空，最长 300 字符）、`markdown`、`createdAt`、`updatedAt`。题库文档包含 `schemaVersion: 1` 和题目列表；独立窗口配置保存透明度、置顶、尺寸、位置与上次选中题目 ID。

主进程将题库存入 `app.getPath('userData')` 下的 `cheat_sheet_bank.json`。第一期上限为 5,000 题、单题 1 MiB、整库 32 MiB；读取、编辑、导入与写入均应用一致限制并反馈具体原因。题目属于该 Windows 工具的独立本地文档，不增加 Rust 核心数据库表；后续若纳入核心数据模型，再完整增加 migration、model、service、binding 与类型声明。

写入串行化，通过同目录临时文件再替换目标文件，成功后才更新内存状态并通知界面。存储损坏时保留原文件并显示恢复提示，不自动覆盖为空题库。窗口关闭前有未保存草稿时提供保存/放弃/取消的键盘可操作选择；退出过程中不丢弃已经提交到主进程的写入。

### 5.2 配置与导入

- 新建和编辑都提供标题输入与 Markdown 编辑区，保存快捷键触发持久化，失败保留草稿。
- 支持一次导入多个 UTF-8 `.md` 文件，一文件对应一道题。标题取第一个非代码块内一级标题，缺失时取文件名；Markdown 保持原文，文内其他标题不拆成题目。
- 同标题题目允许共存，ID 保持独立，搜索结果展示必要的更新时间进行区分；重复导入明确提示新增数量，不静默覆盖旧题。
- 导出所选题目为 `.md`，文件名清理非法字符。导入校验完成后一次提交；任何超限或读取失败均报告具体文件并保持旧库有效。
- 删除需要窗口内确认，初始焦点落在取消按钮；编辑有未保存内容时切题、导入、删除或关闭都先处理草稿。

### 5.3 搜索与阅读

只按标题搜索，不以正文命中代替用户要求的标题检索。标题和输入进行 Unicode NFKC 规范化、大小写归一化与空白归一化；空格分隔的查询词全部需要命中。排序依次为完整匹配、前缀匹配、包含匹配，再按更新时间与 ID 稳定排序。空查询展示全部题目，无结果显示空状态并允许清空搜索。

搜索结果使用限制高度的滚动列表，渲染数量受分页/窗口化限制，不一次创建 5,000 条 DOM。上下键选中，Enter 阅读；切换题目后内容滚动归零，切换结果不删除题目。

Markdown 支持标题、列表、引用、链接、代码块、表格与公式，复用现有渲染/清理函数；代码字体跟随应用配置。第一期不自动加载远程图片、嵌入网页或执行 Markdown HTML 脚本；本地图片附件管理另行扩展。外链通过既有白名单路径处理，不允许 renderer 导航到不受控页面。

## 6. 快捷键与焦点

所有快捷键可在窗口内快捷键配置视图设置，提供恢复默认、冲突说明和重试。复用应用现有快捷键设置与冲突检查，不能另起一套与插件或其他功能无感冲突的注册器。以下为拟定默认值，实施时核对现有默认值和实际注册结果。

### 6.1 全局操作（其他软件具有焦点时仍有效）

| 操作 | 默认快捷键 | 行为 |
| --- | --- | --- |
| 显示/隐藏 | Ctrl+Alt+Q | 创建或切换可见性，隐藏不销毁 |
| 搜索标题 | Ctrl+Alt+F | 打开并聚焦搜索框，全选当前查询 |
| 上一题/下一题 | Ctrl+Alt+Left / Right | 在当前结果序列中切题，不抢焦点 |
| 向上/下滚动 | Ctrl+Alt+Up / Down | 当前正文小步滚动，不抢焦点 |
| 上一页/下一页 | Ctrl+Alt+PageUp / PageDown | 正文按可见高度翻页，不抢焦点 |
| 降低/提高透明度 | Ctrl+Alt+- / = | 每次调整 5 个百分点 |
| 移动窗口 | Ctrl+Alt+Shift+方向键 | 每次移动 20 像素，保持可恢复 |
| 缩小/放大窗口 | Ctrl+Alt+Shift+- / = | 同步调整宽高，限制最小值和屏幕边界 |
| 恢复可读窗口 | Ctrl+Alt+0 | 恢复默认尺寸、可见位置和 90% 透明度 |
| 切换置顶 | Ctrl+Alt+T | 更新原生窗口置顶状态 |
| 关闭小抄窗口 | Ctrl+Alt+Shift+Q | 处理草稿后销毁窗口，保留唤起热键 |

始终保留显示/隐藏与搜索热键；其他全局阅读热键仅在窗口可见时注册，隐藏/关闭即释放。隐藏后不响应切题、滚动和移动。主进程命令统一路由，避免将未加载时的事件发送给空 renderer；正文滚动只对已就绪视图发送。注册部分失败时逐项展示失败状态，已成功的快捷键继续可用，屏幕保护不因快捷键失败而关闭。

### 6.2 窗口内操作

| 操作 | 默认快捷键 |
| --- | --- |
| 搜索 | Ctrl+F |
| 选择结果/打开 | Up、Down、Enter |
| 新增/编辑/保存 | Ctrl+N、Ctrl+E、Ctrl+S |
| 删除当前题目 | Ctrl+Shift+Delete（进入确认） |
| 导入/导出 | Ctrl+O、Ctrl+Shift+S |
| 快捷键帮助/配置 | F1、Ctrl+, |
| 前后切换控件 | Tab、Shift+Tab |
| 执行按钮/确认 | Enter、Space |
| 返回/取消/隐藏 | Esc，依次关闭内部视图、退出搜索，再隐藏窗口 |

配置字段、滑动条、删除确认和错误重试全部具有清晰的键盘焦点。中文输入法组合输入期间不拦截候选确认按键。编辑区里的方向键、Home/End、PageUp/PageDown 保留文本编辑行为；全局组合键和输入光标行为明确区分。涉及未保存草稿的全局操作进入受保护的确认视图并聚焦，用户决定保存、放弃或取消，不静默丢弃编辑。

## 7. 模块和接口

拟新增文件（接口名称为设计目标，不代表当前已经存在）：

- `desktop/src/contracts/cheat_sheet.ts`：题目、配置、搜索结果、窗口状态、命令联合类型与 `CheatSheetApi`。
- `desktop/src/main/cheat-sheet/bank.ts`：校验、标题搜索、导入解析、串行持久化；纯逻辑拆出以便单测。
- `desktop/src/main/cheat-sheet/window.ts`：系统支持判断、原生窗口创建、保护、透明度、位置与资源释放。
- `desktop/src/main/cheat-sheet/ipc.ts`：白名单 IPC 与调用方检查。
- `desktop/src/windows/cheat-sheet/{App.vue,main.ts}`、`desktop/cheat_sheet.html`：独立 Vue 视图与入口。

拟修改的既有边界：`preload.ts`、`main/index.ts`、`contracts/app_config.ts`、`main/app-config/manager.ts`、`main/shortcuts/service.ts`、`vite.renderer.config.ts`，以及现有设置/功能入口中必要的接入点。按需复用现有 UI 组件与主题变量，不修改插件权限模型、不加入新依赖。

IPC 使用 `cheat-sheet:*` 前缀，包含 `get-state`、`list/search`、`save-question`、`delete-question`、`import-markdown`、`export-markdown`、`update-settings` 与受限窗口命令。主进程校验输入结构、大小与调用方窗口，不能信任 renderer 提供任意路径或 BrowserWindow ID。文件选择与读写全部由主进程处理。

题库由主进程持有，renderer 仅保存当前视图和未保存草稿。切题、移动和透明度等全局操作进入同一个命令入口。窗口关闭时解除 renderer 订阅，注销临时全局快捷键、窗口监听与定时保存任务；应用退出时注销全部快捷键并等待已提交写入完成。非 Windows 平台不创建窗口、不注册本功能全局快捷键，入口显示平台限制。

## 8. 验证与验收

### 8.1 自动检查

1. 主进程单测：标题中文/英文/大小写/全角/多关键词匹配与排序、重名题目、导入标题解析（排除代码块）、大小上限、损坏题库、写入失败、并发保存。
2. 窗口与 IPC 单测：显示前保护、非 Windows 阻止创建、非法 opacity/payload 拒绝、未就绪命令、关闭后重建、隐藏释放阅读热键、调用方限制。
3. renderer 行为测试：搜索选择、切题归零、无结果、编辑保存失败保留草稿、IME、焦点恢复、每个产品操作的键盘路径。
4. 运行受影响文件 lint、相关 Vitest、`pnpm --dir desktop run build:app` 和 `git diff --check`。全仓既有失败与新增失败分别记录，构建通过不等同于防捕获通过。
5. 使用终端、进程检查与本地 CDP 验证独立窗口、DOM、快捷键命令和资源释放，遵循用户现有不使用 Computer Use 的偏好。

### 8.3 用户工作流验收

提前新建或导入多道 Markdown 题目 → 重启后题库仍在 → 仅通过快捷键唤起搜索 → 输入标题 → 选题阅读 → 切回其他应用后仍可切题、滚动、调透明度和移动 → 隐藏释放临时热键 → 再次显示保持查询和阅读位置 → 关闭后重新唤起恢复配置。整个流程无必需的鼠标步骤。

## 9. 实施顺序与评审点

确认本设计后，编写实现计划并按以下顺序推进：契约与题库纯逻辑及测试；受保护窗口与 IPC；独立 Vue 搜索/编辑/阅读视图；统一快捷键和配置接入；构建与本地运行；逐项兼容性验收和正式使用文档。

当前设计自查：三项原始需求均有对应行为与验收；全部新增共享目标已纳入矩阵；目标能力与已验证事实分开；不把保护标记、mock 测试或构建结果当作真实防捕获证据。
